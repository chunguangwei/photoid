## 发布前必须处理的隐私问题

`google_mlkit_face_detection` → `MLKitCommon` → `GoogleDataTransport` 存在于依赖中。Google 的 [iOS 数据披露说明](https://developers.google.com/ml-kit/ios-data-disclosure) 和 [隐私条款](https://developers.google.com/ml-kit/terms) 明确区分：照片与检测结果在本机处理，SDK 仍收集诊断与使用指标。

因此当前“照片不上传”有依据，而“无任何统计、零网络请求、Data Not Collected”缺乏依据。这里没有抓到本机版本的实际网络流量，不能把 SDK 文档当作一次已经完成的抓包测试。再次送审前须基于最终 SDK 版本与归档隐私报告复核 App Store Connect 问卷及清单。

可选择保留 ML Kit 并准确披露，或后续在 iOS 以 Apple Vision 替换人脸检测并重新做功能/网络回归；本次不在未经回归情况下替换核心算法。

## UI 走查范围与方向

审查启动页、首页、规格详情、自定义规格、相机、裁剪、编辑、检测保存、KB 工具、相册、设置及更新弹窗；参考既有英文真机截图。自动化布局与离线渲染的验证结果在收尾时追加，不能替代相机授权、ONNX 推理和系统照片库保存的真机验证。

现有首页把“拍照 / 换底 / KB / 相册”并列，最独特的自定义要求与文件交付能力不突出。建议定位集中在“报名照片交付”：用户拿到一份机构要求，建立可复用规格，检查实际输出，再按所需命名交付；避免仅添加大量无关联工具。

后续差异化版本可考虑：可复用的交付任务、要求来源与核验日期、实际文件尺寸/KB 报告、非政府承诺明确的检查结果、原图与修改记录、文件导出。本次已实现原始 JPEG 与 JSON 文件检查报告导出、参考性结论和自定义规格优先入口；交付任务、要求来源和修改历史仍是后续建议。均不构成过审保证。美颜/瘦脸不应作为护照等严格证件场景的默认操作。
