# 1.2.0（51）：把找照片收成三个动作

用户反馈旧流程太复杂，当前主路径调整为：**选尺寸 → 选一批照片 → 点一张开始制作**。不再先建任务，不提供示例创建入口。50 的安装包、截图及发布草稿属于上一轮候选，不代表本版界面。

原有冷启动加载效果保持不变，本轮不新增或修改动效。

## 当前交互

- 首页直接打开 AI 找照片。选择 33 个常用规格之一，支持名称/用途/像素搜索；也可手动补充尺寸、KB、底色，自定义编辑保留已有值。
- 相册批量选择为主按钮，文件夹为次按钮；文件多选、子目录和格式/隐私说明放在更多选项中。相册数量与连续选择手势由系统决定，不宣称所有系统均支持滑动勾选。
- 选中后立即本机分析。完成时收起来源选项，让结果网格优先可见；可重新选批次。取消重新选图保留原有结果。
- 只有“优先查看”和“全部照片”两个视图。点图预览，判断依据按需展开，主操作为“用这张制作”。尺寸变化复用已完成的人脸分析，重新计算排序，不强制再选照片。
- 仅在明确采用时保存原图和规格，并直接进入原有编辑器。单选/拍照入口保留。制作记录、已有文件检查及多输出/OCR 等旧功能保留在次要入口。
- 原有记录不自动删除；只移除新的示例入口。开发测试素材和内部测试通道不是面向用户的示例功能。

## 原生批量选择

- iOS：PHPicker，仅获得用户选择的 NSItemProvider。保留提供方句柄，逐张按需读取；不提前复制 500 张原图。原始大小/像素限制、缩略图缓存上限、停止/退出清理、采用前指纹复核保持。
- Android：系统 Photo Picker，按平台/SDK 扩展支持的数量上限选择；不可用时走 SAF 多选。构造/打开失败都复位 pending，避免永久 busy。
- 云端图库/文件提供方可能下载用户明确选择的内容；处理模型不上传照片，不建立全相册索引或身份向量库。
