# 报名照片交付增量设计

用户批准保留所有现有功能，新增已有照片检查、报名任务、多版本交付和可读清单。目标是形成真实使用流程和可复现审核证据，不保证 4.3 通过。

- 继续 Flutter，中英双语、深浅主题、Android API 26 / iOS 15.5；不移除现有工具，不新增账号、广告、云端照片处理。
- 独立“已有照片检查”入口：从 Files 选择文件（原字节），或从系统图库选择；填写自定义要求后检查 JPEG、解码、实际像素、KB、比例；检查不改写输入。图库可能由系统提供转换副本，界面说明范围。失败项可进入已有编辑器制作。
- 新增本地报名任务：名称、要求说明、来源链接（仅保存）、核对日期、可选来源截图、原图。任务保存在 App Documents；删除任务删除其本地副本，不操作用户系统原图。不抓取来源链接。
- 每任务最多 5 个输出要求，各有名称、尺寸、KB、底色、唯一 ASCII 文件名。复用现有自定义规格表单，通过回调返回规格；旧入口行为不变。
- 一张源图用于每个版本，使用原编辑器分别调整裁剪/底色。ResultPage 增加可选回调与固定输出要求：明确保存到任务，实际不符指定要求的结果不能标记完成。编辑器的底色变更必须与任务要求一致，否则提示并拒绝保存，不悄悄覆盖要求。
- 可以恢复任务、重做某一版本，修改要求或替换原图使对应已完成输出失效；替换原图先确认。文件命名改变也使输出失效，导出时无重复文件名。
- 全部版本完成且重读实际文件通过属性检查后，导出一个 ZIP，包含 JPEG、每份 JSON 与当前界面语言的 CHECKLIST.txt；分享动作不等同用户实际保存。不把 PNG 当 JPEG，不导出半成品、不复用陈旧报告。
- 同一任务的存储操作串行；JSON 原子替换，避免中断读出半文件；损坏单任务不影响其他任务。对读取图片设 30MB 文件和 24MP 解码上限；导出最多 5 项，限制总体读取避免内存失控。
- 首页新增任务与检查入口，旧自定义/拍照/换底/KB/相册/规格库保留。玻璃只用于导航，内容实底。新页面适配 320px 与 130% 字号。
- 保留 ML Kit 技术指标披露，新增任务本地存储/删除/缓存说明。商店截图与演示未完成前不提交审核；新文案只陈述已实现功能。OCR 为后续项，不在本轮范围。
