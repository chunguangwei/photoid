# 报名要求识别与照片交付工作流

状态：已完成独立 builder check，用户已于 2026-11-06 确认具体设计并授权实施。用户已同意“示例任务＋要求截图识别＋交付总览，补齐 iPad 验收”的方向。本文件不代表已实现，不承诺审核通过。

## 目标与边界

让首次使用者能从一份真实的照片要求走完“确认要求—分别制作—核对实测属性—交付”。保留现有拍摄、换底、美颜、裁切、压缩、规格库与相册。继续使用现有 Flutter 项目、原 Bundle ID、原 App Store 记录、iOS 15.5 / Android API 26、中英双语及深浅主题。不新增账号、广告、云端识别或付费服务；不做证件、身份验证或官方认证。

本轮不增加后台网页抓取、任意 PDF 解析、分享扩展、云同步或自动上传报名系统。不为了降低二进制相似度混淆、替换框架或改包名。

## 1. 对所有用户开放的示例任务

任务页和首页任务入口提供“体验示例”，首用时可见；不识别审核账号或隐藏功能。示例素材随包离线可用：采用此前已核对授权的公开示例人像，以及自制的虚构报名要求截图，文案明确“演示要求，并非任何机构标准”。新增素材记录来源及许可；公开人像不暗示人物背书。

用户点击后创建普通可编辑、可删除的本地任务，名称带“示例”；包含来源说明、要求截图、一张原图、两份未制作输出：Main 480×640、蓝底、20–100 KB、photo_main；Profile 300×400、白底、10–100 KB、photo_profile。未实际生成时不显示通过或完成。重复点击默认打开已有完好的示例任务；删除后可重建。创建失败清理本次半成品，不修改用户任务。

提供三步提示：确认两份要求、分别制作、核对并导出。用户仍使用真实编辑器和真实检查/ZIP 导出逻辑，不预制虚假的检查状态。具体验收目标是审核人员无需自行找素材即可操作，视频可用快进但不宣称设备统一完成时长。

## 2. 要求截图文字识别与确认

在任务内要求截图区域提供“从截图提取要求”，支持沿用已附截图或经现有 Files / Photos 入口新选图片。仅处理用户明确选择的图片，受现有图片体积和解码上限保护。不会读取整个图库。支持中英文印刷体截图；不支持的格式、无文字、超限、识别失败均给出原因及手动填写入口。

技术选择由开发方建议：iOS 使用 Vision 的 VNRecognizeTextRequest，通过小型原生 channel 异步识别；按系统支持语言选择中文简体及英文，不依赖新下载。Android 使用 ML Kit Text Recognition v2 的随包中英文模型，禁止使用需临时下载的 Play Services 版本。仅原生识别库与模型随包，字段解析在 Dart 完成；识别调用接口可注入测试替身。实施前验证最低系统支持和可用语言，不支持时明示并保留手工路径。新的 SDK 需按最终 privacy manifests 更新隐私说明及商店披露，不把本机识别写成整 App 零网络。

识别结果先作为未确认草稿，不自动保存成输出要求。确认页展示原截图/文字、匹配原文片段、候选值、可编辑字段。识别基于可解释的规则提取明确的像素尺寸、KB 上下限、JPEG/JPG 格式、支持的纯色底色。第一版只解析像素单位和 KB；毫米/DPI、MB、文件名、机构名称及人像比例不自动换算。仅出现 480×640 但未标明宽高方向时，必须让用户确认宽高；不能悄悄倒置。

保守处理：单个明确配对、带单位的尺寸可填入草稿；“不超过 100 KB”表示只有最大值，不编造最低值；区间 20–100 KB 才给上下限。KB 字节口径沿用现有 1024，并在确认处说明，无法判断机构使用哪种口径。多个尺寸、多个底色或互相矛盾的候选均列出，不擅自匹配到某个报名用途。第一版每次确认生成一份输出，用户可从同一截图再次确认下一份；最多五份，达到上限则先提示管理已有项。

未识别字段保持“未提供/待填写”，不能用常见证件照规格冒充识别值。保存前用户必须确认必填尺寸、文件名、底色，范围需满足现有可制作边界。截图要求不是 JPG 或尺寸/范围不受支持时明确提示不支持，不自动改写成 JPG 标准；可取消或由用户主动修订。即使候选无冲突，也要求点击“确认并添加”，不声明权威正确。

取消不改变任务输出；重新选择截图/退出后忽略过期异步结果。识别不能覆盖原有输出，编辑既有要求走现有确认和失效逻辑。截图/识别草稿只保留在本地，用户确认后保存简短原文摘录及手动确认标记到对应输出；不把“用户确认”解释成机构认证。旧任务 JSON 兼容加载，新字段为可选并有默认值；不破坏 schemaVersion 1 的读取与恢复。

来源确认的版本规则：摘录记录绑定当前 evidenceRevision，并绑定当前尺寸、KB、JPEG 格式及底色的要求指纹（不含文件名）。修改以上属性即清除确认标记；仅改文件名保留来源确认，但成片是否失效沿用现有存储行为。替换要求截图后，对全部旧摘录清除当前确认状态，标注“来源已变更，需重新核对”，保留摘录文字供参考但不作为当前截图证据；导出同时明确该状态。重新识别不能让原来已制作的输出悄悄改要求，必须通过正常修改要求及成片失效路径。用户可手工重新核对确认，记录新版本。

## 3. 交付总览

任务页增加“交付总览”，每份显示文件名、要求像素/KB/格式/底色、制作状态，以及实际像素、精确字节数和 KB；背景只显示用户选择的要求与编辑配置，不假装独立测量背景颜色。未制作不显示实测值，缺失/损坏/不满足要求显示问题及“重新制作/修改要求”入口。

页面进入、保存成片后及主动刷新时读取真实文件并调用现有 inspectPhotoFileWorker；不把 ready 布尔值等同再次检验通过。读取期间显示检查中，顺序处理最多五份，切换任务忽略旧返回。缓存按任务源 revision / output revision 区分。总览定位到对应项；报告与预览复用同一检查模型。导出仍调用现有串行快照构建，所有输出制作完成且实际文件通过才允许导出，不由页面缓存放行。

选中要求的原文片段可以展开查看；ZIP 的逐份 JSON / CHECKLIST 补充对应摘录和“用户确认，来源未经独立验证”。不默认把完整要求截图或源照片放进 ZIP，避免无意分享额外资料。

## 4. 首次体验和定位

取消现有固定六秒启动倒计时和“跳过”广告式提示。正常启动直接进入首页，模型按需/后台预热；首张处理遇到加载提供真实加载状态、失败重试和取消。保留现有 Material / 玻璃导航体系，内容区域实底，不进行全站换肤。

首屏强调报名任务、导入要求与已有文件检查，既有工具继续可达。首页任务卡显示进行中数量和最近任务入口。桌面品牌保留 PhotoID，中文可用“PhotoID 照片工作台”，商店仍沿用 PhotoID Studio；具体字符长度按设备验证。名称及介绍只反映实际能力，不靠改名解决 4.3，不含官方、认证、独有、保证受理等表述。

## 5. 验证及发布边界

自动验证：解析器覆盖中英文、宽高歧义、大小上限/区间、多候选、冲突及不支持单位；旧任务兼容、示例重复创建/失败回滚、确认取消无改动、异步过期结果；文件丢失/损坏与陈旧 ready 不可放行；通过已有导出及编辑回归。新增关键页面检查 320pt、130% 字号、中英/深浅，OCR 失败和取消。

真机：iPhone 和 iPad 兼容模式分别完成示例创建、Files/Photos 选择、识别截图及人工确认、两份裁切与保存、重进任务、总览实测、ZIP 分享和 Files 解压。iPad 以实际设备操作为证据，远程控制不可用时记录缺口并由用户协助，不写成已通过；本轮仍 iPhone-only，不自动新增 iPad 原生支持及截图要求。离线新安装验证随包识别，中文英文均检查；Android 实机验证识别与正式签名覆盖升级。

发布材料：仅用最终真实 UI 重新采集中英文截图；制作 60–90 秒真实流程视频、简短旧版/新版行为对照及审核操作路径。给所有用户提供同一示例入口。审核说明只陈述已验证功能，代码历史作为辅助。先等 Apple 当前澄清回复并结合答复调整；本轮实现完成不自动再次提交或新增申诉。版本号/构建号在实际打包前按 ASC 已存在构建核对，不能覆盖 49。
