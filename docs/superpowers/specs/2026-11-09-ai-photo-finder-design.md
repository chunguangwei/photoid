# 按任务要求在本机寻找照片 — 增量设计

状态：用户于 2026-11-09 明确确认方案并要求保留人工选图入口；现按此实施。验收状态见发布准备文档。用户要求在现有手动选图之外增加目录照片智能筛选，并在实现后同步全量文档和 App Store 文案、图示。

## 一、目标和已有基础

主流程：确认报名照片要求 → 选择可访问目录 → 本机筛选、解释排序 → 用户挑选候选 → 原有裁切/换底/压缩 → 文件实测总览与 ZIP 交付。保留所有人工选图入口、现有工具和 2026-11-06 已开发的示例/OCR/交付功能。在现有 feat/requirements-workflow 分支继续做增量；不丢失原目录 ios/Runner/Info.plist 的用户改动。

本次建议以任务驱动的自动筛选与排序为核心；自然语言输入搜图和人物身份搜索不属于本轮默认范围。用户如选择同时做自然语言搜图，需补充语义模型性能/下载设计后再实施。不会宣称其他应用没有这一模式，也不保证 4.3 通过。

## 二、模型选择与国内外使用

尺寸、格式、字节数由文件解码/元数据确定，不让大模型猜。人脸检测属于真正的本机模型推理；清晰度、曝光、可裁切分辨率由图像计算给参考值。语义相似度不当作证件照适用性或机构受理概率。

推荐第一版：iOS 使用系统 Vision 人脸检测；Android 使用 ML Kit 随包人脸模型（已有依赖可复用）。两端模型在安装后的本机使用，不要求用户从 Google/Hugging Face 临时下载，不依赖在线照片处理。Android 不选 Play Services 动态下载版。现有 ML Kit 技术诊断披露保留；不得把本机图像分析写成整个 App 零网络。iOS 新能力不意味着移除已有 ML Kit 依赖或解决既有 arm64 模拟器兼容问题。

EmbeddingGemma 2 官方资料确认是多模态嵌入模型：740M 总参数，视觉/文本可按模态加载，官方模型卡列 Apache 2.0，支持图像检索。它适合作为后续可选的文字/图片语义搜索层，但不能单独判断尺寸够不够、是否只有一人、裁切后是否够清晰。本轮不把它加入必下载或随包大模型。MobileCLIP 系列可列备选，不能在未测中文检索、许可及转换一致性前宣称更好。

已查到 EmbeddingGemma 2 国际 Hugging Face 仓库与国内 ModelScope 同名模型页，并核对两站文件元数据：model.safetensors 均为 1,488,915,288 字节，SHA-256 均报告为 197a32965d4b1105faf060417baa899e193fb73cd401f42ec9295234d5553d79。原始权重约 1.49 GB，未完整下载后自行计算哈希，也未验证移动量化包、国内外网络覆盖和手机推理。如果后续采用，必须实际验证两地下载、模型/分词器/图像预处理版本、许可、SHA-256、一致推理、断点续传和取消；下载失败不能阻断基础筛选。不执行下载来的代码，不把外部用户照片用于测下载服务。

## 三、入口与目录权限

首页增加“AI 找照片”，任务页原图区域增加“在目录中寻找”。先选择已有任务或填写至少一份要求，避免脱离任务盲目打分。已有任务最多五份输出；候选展示对各份输出的像素适配情况。首页入口选任务后进入同一筛选流程，不再另建独立人像处理系统。

iOS 用 UIDocumentPickerViewController 的 folder 类型返回 security-scoped URL；只访问用户亲自授权的目录，通过 NSFileCoordinator 读取。目录许可保持到本次结果会话结束；采用照片前先复制到 App 私有任务，再释放外部许可。取消、退出、权限撤销、异常均释放。第一版不持久化目录书签或后台扫描，不申请整个相册权限。

Android 用 ACTION_OPEN_DOCUMENT_TREE 及 content URI 枚举，不能把 URI 当普通文件路径。不申请 MANAGE_EXTERNAL_STORAGE。Android 11+ 不能选择 Downloads 根目录；界面解释系统限制，提供“选子目录”或“批量选择文件”作为等价入口。只要求读取，不改写源文件；第一版不持久化 URI 权限。系统图库继续通过既有人工选图入口，第一版不自动遍历全图库。

文件提供器可能是 iCloud 或第三方网盘。仅分析已在本地可读取的文件；能识别未下载状态时跳过并提示先在 Files 下载。不得为扫描主动请求云端下载；提供器无法证明本地状态时先说明并跳过。Android 远程 DocumentProvider 无统一离线标记，默认目录扫描限外部存储/明确本地文件提供器；未知提供器回退显式多文件导入并提示提供器可能取回文件，不能虚构完全离线保证。

## 四、扫描、分类和排序

第一版 JPEG/PNG 进入完整评分；HEIC/HEIF 走原生受限解码/转为 App 内 JPEG 分析副本，需明确来源格式与副本转换，不改原图。若目标平台的转换未验证，则列为“当前不支持，改用图库选图”并准确计数，不把未分析文件当不适合。沿用单文件 30 MB / 24 MP 安全界限，超限逐项说明；本轮不默认全量解码 48 MP 照片或擅自提升现有安全上限。

默认不含子目录，用户可主动启用；深度最多 5，避免符号链接、别名循环和包目录。单次最多检查 2000 个目录项、分析 500 张图片，达到上限显示“部分结果/达到上限”，不声称已扫描完目录。逐份解码，分析图长边限制约 1280px，原生先读图像头并检查限制，再做缩略解码；原始尺寸按 EXIF 旋转后的显示方向记录。缩略图和坐标变换必须保持一致。原图超限时不能先全量解码再拒绝。

检测保留全部人脸数量及每张脸的归一化框；不能直接复用旧合规检查“只取最大人脸”的结果而忽略多人。可用姿态角为参考，缺失检测值标为未知，不按零角度/已睁眼处理。第一版不推断身份、年龄、性别、种族，不做人脸身份聚类或持久化身份向量；不宣称已检测所有遮挡、头顶完整或表情符合机构标准。

候选分组：
- 优先查看：检测到单人、人脸方向/有效像素等有可用证据，并且按当前要求有足够的预估裁切空间。
- 需人工核对：多人、角度较偏、小脸、质量指标较弱或检测值缺失等；展示具体原因，允许用户仍然选择。
- 当前像素要求不匹配：保守估计的可裁切像素不足，解释对应哪份要求；可查看原图并人工选择，不将低分设成禁止使用。
- 无法判断/已跳过：未检测到人脸、格式不支持、损坏、未下载、超限、访问失败等，分清原因。未检测到人脸不等于确定不是人像。

排序先看当前任务五份要求的预估像素覆盖数，再按单人、较正姿态、脸部有效分辨率和清晰度参考排序。使用清晰的等级和理由，不显示未经校准的“通过概率”或“AI 合规分”。iOS 可选 faceCaptureQuality 仅作额外参考，不能与 Android 不同语义的数值直接比较。阈值在公开测试样本上确定并记录，不伪称已获得机构验证。

建议裁切框按人脸位置、目标宽高比和画面边界计算；用户可以查看预估区域、原始像素和各输出的适配提示。人脸框不是头部完整边界，不把框上方估算当发顶定位。最终仍逐份进入现有编辑器，文件属性以最终实际 JPEG 检查为准。KB 压缩可调整，因此不因原图文件较大直接淘汰可制作照片。

## 五、结果、取消和任务接入

结果卡含缩略图、文件名、相对目录、显示方向后的尺寸、检测到的人数、推荐/核对理由和各输出像素适配；不向用户暴露无意义的沙盒绝对路径。允许分组筛选、原始文件名/相对路径搜索、查看原图及“用这张制作”。这不是自然语言语义搜索。

扫描中显示已检查/已分析/已跳过数量，支持停止并保留已得到的部分结果；关闭页面、换目录、改任务要求后用会话 token 忽略旧返回。停止计算不代表整个目录已检查。退后台暂停/取消本轮，不在后台长期扫描。结果只保存在本次会话的内存和私有缓存，不写入公共索引；缓存会话退出清理，异常残留按不超过24小时 TTL清理，用户有清除入口。

选中后重新校验文件可访问性、大小/修改标识；有变化或目录许可撤销时重新分析或要求重新授权，不能套用旧推荐。记录分析所对应的任务要求指纹，当前要求变化时重新排序，不把旧结果当新要求的结论。只有用户点击使用才保存任务原图副本；任务已有原图时复用原有替换确认，受影响成片失效。不复制整个目录、不删除、移动或重命名源文件。

不得在默认 ZIP 中附加扫描清单、未选照片、目录树、面部框/特征。现有交付包仅包含用户选择并制作的照片、明确确认的要求摘录和文件检查报告。隐私政策新增选定目录本机分析、临时缓存、来源复制和清理范围。

## 六、示例与验收

新增对所有用户可见的“体验 AI 找照片”：使用许可明确的随包样本目录（单人适合、偏角/较低质量、多人、无检测结果等）。示例目录与普通目录走同一原生分析和真实评分路径，不预存假的检测结果；不得仅对审核人员开放。样本声明仅演示、不暗示人物背书；新增图片前确认许可，不取用户真实照片上传做测试。

测试：目录取消/拒绝/权限撤销，Android URI 与根 Downloads 限制，多文件回退，子目录开关/循环/上限，损坏/超限/未下载/不支持格式，EXIF 旋转，单人/多人/零人脸/缺失姿态数据，低清晰度参考，裁切框越界和输出覆盖，扫描取消/过期返回/要求变更/文件变更，替换原图和陈旧成片失效，内存峰值与离线首次运行。服务用可注入原生检测器验证评分/状态机；原生模型必须用真实有许可样本在设备上验证，不能把模拟返回当模型验证。记录误检/漏检，保留人工纠正路径。

iPhone 13、iPad 兼容模式及 Android 真机完成“目录授权—候选筛选—选择—多规格制作—导出”闭环。用 100 张样本做时间/内存/取消响应记录，不预先承诺几秒扫完。真机不可用时准确标为未验收；正式商店截图/视频必须来自最终真实运行版本。
